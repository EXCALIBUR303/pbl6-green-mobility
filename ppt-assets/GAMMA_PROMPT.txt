SLIDE 6 — Core Problem Solved: Preventing Overbooking
This is the most important slide. Explain:
- Two students clicking "Book" on the last seat at the same instant is a
  classic race condition
- Checking availability and then updating in two separate steps leaves a gap
  where both requests can pass the check
- Our fix: fold the check into the write as one atomic SQL statement
Include this SQL prominently as a code block:
UPDATE vehicle_slots SET booked_count = booked_count + 1
WHERE slot_id = ? AND booked_count < capacity;
- If it updates one row the seat is reserved; if it updates zero rows the slot
  was already full and the booking is rejected
- The guarantee lives in the database, not in the browser or the Java code
